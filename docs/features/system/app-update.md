# 应用内更新

**系统与隐私** · 内置能力（无开关） — 检查新版本，发现后把安装包交给浏览器下载。

## 怎么用

| 位置 | 没有更新 | 有更新 |
| --- | --- | --- |
| 主页 → 模块版本 | 只显示「知友 1.0」，与平时一样 | 多出一截绿色文字「知友 1.0 · 发现新版本 1.1」，整行可点 |
| 设置 → 更新 → 检查更新 | 副标题写「当前 1.0」 | 副标题写「当前 1.0 · 有新版本 1.1」，结果用弹窗反馈 |

两处点开是同一个弹窗：版本号、发布日期、更新内容、主按钮、「以后再说」。
主页进入时后台静默查一次（24 小时最多一次，失败也计一次，界面上不报错），手动检查不受这个限制。
「以后再说」只关弹窗，主页那行提示保留到装上新版本为止。

## 更新从哪来

版本清单是仓库根目录的 `update.json`，三个源并发读，取第一个成功的（每个 4 秒超时）：

| 顺序 | 来源 | 说明 |
| --- | --- | --- |
| 1 | jsDelivr | 读仓库文件的 CDN，国内通常可用 |
| 2 | gh-proxy + raw | 第三方加速，绕开 raw 域名打不开的问题 |
| 3 | GitHub API | 未登录 60 次/小时，放最后兜底 |

比较只看 `versionCode`：清单里的数字大于本机版本号才算有新版本，与「git 有没有新提交」无关——
日常改代码不会提示更新。

## 下载

弹窗出现时并发实测该安装包的两条线路：各发一个 64KB 的 Range 请求（3 秒上限），按读完的耗时选最快的一条，主按钮直接打开它。

- 点了只在系统浏览器里打开链接，下载与安装用浏览器自己的权限：模块不申请安装权限，也不经手文件。
- 几条线路都连不上时，按钮变成「打开发布页」，走 GitHub Releases。
- 覆盖安装靠签名校验，包不对系统会直接拒绝。

## 注意

- 装完要重启微信：模块代码在微信进程里加载，不重启还是旧的。
- 刚发版时 jsDelivr 可能还有几分钟到几小时的旧缓存，这段时间 gh-proxy 那条源是新的。
