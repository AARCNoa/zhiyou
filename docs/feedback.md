# 问题与建议

> 提问前请先读 [提问的智慧](https://github.com/ryanhanwu/How-To-Ask-Questions-The-Smart-Way/blob/main/README-zh_CN.md)。

**唯一渠道是本仓库的 Issues。** 私聊与其它渠道不处理。

## 提交前

1. 搜索已有 Issues 与 [常见问题](faq.md)，避免重复；
2. 用最新源码重新编译一次再确认；
3. 排除干扰：LSPosed 里只勾选知友并重启微信；
4. 一个 Issue 只报一个问题；模板每一项都要填。

## 问题反馈必需内容

缺任意一项会被直接关闭，重复违反会被拉黑。

| 项 | 获取方式 |
|---|---|
| LSPosed 详细日志 | LSPosed → 设置 → 禁用详细日志：关 → 日志 → 右上角菜单 → 保存 → 上传压缩包 |
| 模块调试信息 | 模块设置 →「调试 / 复制调试信息」→ 粘贴 |
| 崩溃日志（闪退时） | 开启「调试 / 崩溃拦截」→ 复现 → 取 `<模块数据>/crashes/` 对应文件 |
| 模块运行日志 | `/sdcard/Android/data/<宿主包名>/WCX/logs/` |

再补充：问题描述（期望 vs 实际）、复现步骤、环境（微信 / 模块 / Android / LSPosed 版本、是否 Root）、
截图或录屏、是否稳定复现。

## 建议反馈

说明四件事，越具体越容易被采纳：

- **使用场景**：解决什么问题，什么情况下需要；
- **期望行为**：功能应该怎么工作；
- **参考实现**：其它应用或模块的类似做法；
- **可选方案**：考虑过的替代实现与取舍。

先确认该功能确实不存在，而不是尚未发现已有实现。

## 处理流程

1. 维护者标记分类；缺内容会等待补充，超时关闭；
2. 建议会评估可行性与适用范围，采纳则进待办，不采纳会说明原因；
3. 已关闭的 Issue 不再讨论 —— 新问题请开新 Issue；
4. 请勿催进度。
